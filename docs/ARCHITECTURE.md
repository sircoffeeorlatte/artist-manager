# Архитектура Media Library

## Основные слои

- **UI**: Vue-компоненты и страницы. Не обращаются к файловой системе напрямую.
- **Services**: API медиатеки, импорта, пользовательской конфигурации и состояния.
- **Repository**: `src/services/mediaRepository.ts` — единая точка доступа к записям медиатеки.
- **Native layer**: команды Rust в Tauri для системных файловых операций и SQLite.
- **Persistence**: SQLite в `app_data_dir`, независимая от папки медиатеки и установочного каталога.
- **Library storage**: корень, выбранный пользователем; приложение создаёт в нём известную структуру каталогов.

## Структура медиатеки

```text
<library-root>/
├─ IRL/{Фото,Видео,Архивы}/
├─ Аниме/{Фото,Видео,Архивы}/
├─ 3D/{Фото,Видео,Архивы}/
└─ wallpapers/
```

Импорт создаёт копию под уникальным именем. Для режима перемещения исходник удаляется только после проверки результата копирования. Временные `.partial` файлы не индексируются и могут быть удалены при восстановлении после прерывания.

## SQLite и жизненный цикл индекса

- Runtime-файл: `media-library.sqlite3` в `app_data_dir` Tauri.
- SQL-схема: `database/schema.sql`; bootstrap-миграция: `database/migrations/0003_runtime_sqlite_index.sql`.
- Миграция применяется Rust-командой `initialize_database()` при старте приложения; версия регистрируется в `schema_migrations` и `PRAGMA user_version`.
- Таблица `media_files` хранит тип, имя, уникальный относительный путь, расширение, MIME, размер, даты файловой системы, время добавления, категорию, JSON-метаданные и статус.
- `tags` и `media_file_tags` хранят много-ко-многим теги. `tag_type='creator'` предназначен для будущей модели авторов.
- `index_state` хранит корень медиатеки, флаг активного сканирования, время старта/завершения, количество обнаруженных/отсутствующих записей и последнюю ошибку.
- Первичная индексация выполняется при первом обращении к корню. Повторное открытие страниц выполняет SQL-запросы без полного обхода диска.
- Успешный импорт вызывает индексацию после записи файлов. Пользователь может вручную переиндексировать медиатеку со страницы «База файлов». После реальной ошибки повторный переход по страницам не запускает сканирование снова автоматически — ошибка отображается и пользователь может повторить индексацию явно.
- Индексатор обходит только известные папки категорий и типов, но поддерживает вложенные каталоги. Символические ссылки не обходятся.
- Список файлов сначала собирается в памяти. Если чтение папки или метаданных завершается ошибкой, транзакция обновления не запускается и старые данные не помечаются отсутствующими.
- После успешного полного сканирования записи, которые раньше были доступны, но больше не обнаружены, получают `status='missing'`. Их теги и метаданные сохраняются.
- Каталог с нулём известных папок типа `Категория/Фото|Видео|Архивы` считается неверно выбранным корнем, а не пустой медиатекой: сканирование прерывается, чтобы не отметить весь индекс отсутствующим.
- UI-запросы по типу читают строки из SQLite. Абсолютный путь формируется при чтении как `library_root + relative_path`; абсолютные пути не являются каноническим идентификатором записи.

## Относительные пути и смена корня

`media_files.relative_path` — уникальный путь внутри текущей медиатеки, разделители в базе нормализованы к `/`. Это позволяет перенести саму папку медиатеки на другой диск без массового обновления абсолютных путей. В конфиге приложения хранится выбранный корень. В этой версии база обслуживает одну активную медиатеку; переключение на другой корень переиндексирует его в тот же каталог записей, а не хранит независимые библиотеки параллельно.

## Ошибки и восстановление

- Ошибка индексирования сохраняется в `index_state.last_error`; флаг `is_scanning` сбрасывается.
- Если приложение завершилось во время сканирования, при следующем запуске stale-флаг сбрасывается и в состояние записывается сообщение о прерывании.
- Если корень недоступен, индекс не обновляется и старые записи не удаляются. Gallery-команда возвращает понятную ошибку вместо пустого результата.
- Временная ошибка чтения не приводит к частичному изменению статусов, поскольку upsert/missing updates выполняются в транзакции после полного сканирования.
