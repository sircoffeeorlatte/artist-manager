# Media Library — локальная медиатека Windows

Приложение для локальной коллекции фото, видео/GIF и архивов. Стек: Vue 3, TypeScript, Vite, Tailwind CSS 4, Tauri 2 и SQLite через Rust `rusqlite` (bundled SQLite, отдельный сервер не нужен).

## Текущие возможности

- Галереи фото и видео с настройкой плотности сетки; видео также имеет TikTok-режим.
- Галерея архивов и открытие файлов внешним приложением.
- Импорт фото, видео/GIF и архивов, копирование или безопасное перемещение, прогресс и журнал операций.
- Выбор отдельного корня медиатеки со структурой `IRL`, `Аниме`, `3D` → `Фото`, `Видео`, `Архивы`, плюс `wallpapers`.
- Сохранение настроек внешнего вида, звука, сеток, обоев и стартовой страницы в `user-config.json`.
- Настоящая SQLite-база в папке данных приложения: индекс файлов, относительные пути, категории, даты, статусы доступности, теги и состояние индекса.
- Страница «База файлов» для просмотра записей, проверки отсутствующих файлов, просмотра состояния SQLite и редактирования общих тегов.

## Как устроен SQLite-индекс

- Файл `media-library.sqlite3` находится в папке данных Tauri (`app_data_dir`), а не рядом с установщиком или файлами медиатеки.
- При первом обращении к новому корню выполняется первичная индексация. Далее галереи читают записи из SQLite и не обходят диск при каждом открытии.
- Переиндексация выполняется после успешного импорта, при выборе другого корня или по кнопке «Переиндексировать» на странице «База файлов».
- Файлы ищутся только в известных каталогах категорий/типов; вложенные папки поддерживаются. Неизвестные расширения, ссылки и служебные `.partial` пропускаются.
- В базе хранится относительный путь. Абсолютный путь восстанавливается при чтении, поэтому перемещение корневой папки на другой диск не требует хранить в каждой записи абсолютный адрес.
- Недоступные файлы получают состояние `missing`; записи и теги не удаляются. Ошибка сканирования останавливает обновление до транзакции, поэтому временная ошибка доступа не должна массово отмечать файлы отсутствующими.
- Теги находятся в `tags` и связываются с файлами через `media_file_tags`. Тип `creator` зарезервирован для будущей страницы авторов.
- Схема документирована в `database/schema.sql`, а runtime-миграция — в `database/migrations/0003_runtime_sqlite_index.sql`.

Подробности: [`docs/SQLITE.md`](docs/SQLITE.md) и [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Быстрый старт Windows

### Требования

Для браузерного превью нужен Node.js LTS с npm. Настольное приложение требует Rust MSVC, Microsoft C++ Build Tools и WebView2 Runtime. См. руководство Tauri: <https://v2.tauri.app/start/prerequisites/>

### Установить зависимости

Запусти `install.cmd`. Он выполнит `npm install` и при наличии Cargo попробует загрузить Rust-зависимости.

### Запуск в браузере

Запусти `run-web.cmd`. Это только превью интерфейса: браузер не может индексировать произвольные папки Windows и напрямую пользоваться встроенной базой Tauri.

### Запуск настольной версии

Запусти `run-desktop.cmd`. При первом запуске Cargo соберёт нативную часть и встроенный SQLite.

### Проверка и установщик

- `check.cmd` запускает проверку типов и сборку фронтенда.
- `build-windows.cmd` собирает Windows-установщик NSIS `.exe`.

## Ограничения текущего этапа

- Индексация выполняется полным обходом известных папок при ручном обновлении/первом запуске нового корня и после импорта. Инкрементальный watcher файловой системы пока не реализован.
- Генерация миниатюр, EXIF и расширенные технические метаданные видео — следующие отдельные этапы.
- Для браузерного режима нет настоящей файловой индексации; база обслуживается нативным слоем Tauri.
- Перед релизом на Windows нужно выполнить `check.cmd`, `cargo check --manifest-path src-tauri/Cargo.toml` и тесты импорта/индексации в настольной версии.
- Дополнительно можно запустить независимые SQL smoke-тесты стандартной библиотекой Python: `python -m unittest tests/test_sqlite_schema.py`.
